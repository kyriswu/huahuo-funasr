# 异步转写、回调与结果确认设计

状态：用户在会话中已确认本设计，并同意增加显式 ACK。目标部署为单机 A10 24 GB ECS + Docker，沿用内置 CUDA 12.6、PyTorch 2.8.0+cu126、完整模型与 FP32 推理。

## 已确认的选择

采用进程内队列、单 GPU 推理线程和独立回调线程。不使用 SQLite、Redis、Celery 或磁盘任务记录。音频在临时目录暂存，解析成功或失败后立即清理；任务、结果与回调状态均在内存。Docker 的 `/tmp` 使用 tmpfs，重启后丢弃任务及结果，不恢复。已注册声纹继续存放在持久化的 `/data/voiceprints`。

这符合单实例需求；数据库队列更适合重启恢复和多实例，但用户明确不需要这些能力。同步请求加长超时仍无法在连接断开后补取结果，因此增加异步入口，保留同步入口。

## 接口契约

- `POST /v1/tasks`：multipart 上传音频，支持 `speaker_count`、`identify_speakers`、`threshold` 和可选 `callback_url`。暂存完成、占用容量后返回 202 与随机 `task_id`。可选 `Idempotency-Key` 在本进程的任务保留期内避免重复提交。
- `GET /v1/tasks/{task_id}`：只返回任务状态、结果是否可取、回调状态，不包含结果，不消费。
- `GET /v1/tasks/{task_id}/result`：返回完整事件，包括固定 `event_id`、任务状态、结果或失败原因。可重复获取，不自动清理。
- `POST /v1/tasks/{task_id}/ack`：下游保存结果后提交 `event_id`。幂等确认，清理结果、释放容量并停止未来回调重试。未完成任务不能提前确认，事件 ID 必须匹配。

任务状态为 `queued/running/succeeded/failed`。未完成时取结果返回 409；已消费结果返回 410；未知或重启前的任务返回 404。失败结果也需要消费，以便下游可靠获得原因。已消费的简要状态保留一小时，且有数量上限；未消费结果没有五分钟或其他自动过期逻辑。

## 回调与并发

回调 POST 完整事件，事件 ID 和正文在重试时不变。下游先保存并按事件 ID 去重，再返回任意 2xx。2xx 与显式 ACK 共享同一个消费操作；先完成的一方负责清理。已在发送的通知仍可能到达，故不承诺只送达一次。

非 2xx、网络错误与超时采用退避重试，有次数上限。达到上限后保留结果供查询和 ACK，绝不重新执行 ASR。回调不持有 GPU 锁。原有同步接口与异步消费者共用推理锁；有排队任务时同步入口返回 429，避免插队。

部署时通过 `CALLBACK_ALLOWED_ORIGINS` 明确允许的回调来源（scheme、host、port），支持指定 VPC HTTP 地址或 HTTPS 地址；禁止 URL 凭证、fragment 和重定向。`CALLBACK_SECRET` 用于 HMAC-SHA256 签名，不复用 API token。签名数据为 `timestamp.event_id.raw_body`，接收方检查时间戳并去重。

## 容量与生命周期

任务上限同时覆盖上传中、排队、运行中、已完成但未消费的任务。另限制暂存音频总大小及单任务结果大小，使待领取结果内存有上界。超额返回 429（含 Retry-After），单文件超额返回 413。无法序列化或结果超限时产生小型失败事件，仍可回调或取回并 ACK。

结果生成后音频即删除，不等待回调。未消费结果只会因 ACK、回调 2xx 或服务重启而清理。回调重试耗尽不触发过期删除。声纹库与任务临时数据独立。

## 验收

覆盖状态与结果分离、重复读取、匹配事件的幂等 ACK、回调签名/失败重试/成功清理、回调与 ACK 竞争、失败任务、音频及时删除、待领取占满后的拒绝与 ACK 后释放、无自动结果过期、临时空间上限、幂等提交、重启清空。使用非 root 断网测试容器完成 API 检查，并用镜像内公开音频执行真实 GPU 异步和回调验收。
